# SocRV 竞赛技术文档目录与写作规划

> 本文件规划正式技术文档的章节、内容边界和证据组织，不代写正文。目录只保留章和节两级，编号最深到 `2.1`；具体模块、寄存器、测试项和报告指标放在所属节内，不再继续拆成 `2.1.1`。

## 1. 本次目录调整原则

上版目录覆盖完整，但把不少实现细节直接设成二级标题，容易出现“标题很多、每节内容很薄”的问题。本版按以下规则合并：

- 单个 RTL 模块不独立成节。I²C Master、SYSCTRL、Timer、UART、GPIO 等放入外设或 SoC 主题中说明。
- 单个器件不一定独立成节。BH1750 和 SSD1306 按“传感器与显示完整链路”组织，硬件连接、驱动和应用相互对应。
- 单项报告指标不独立成节。资源、时序、DRC、功耗统一放入“FPGA 实现与签核结果”。
- 单个测试用例不独立成节。ISA、DiffTest、RT-Thread、传感器测试按验证对象分组。
- CPU 是作品重点，可以保留较细的二级结构，但每节必须覆盖架构、实现和验证三部分。
- 附录承担寄存器表、命令清单、构建步骤和完整测试数据，避免正文被查表材料打断。

调整后的目录共 10 章，正文二级标题约 40 项。整体阅读路线仍是“项目目标—总体架构—CPU—SoC—外设应用—软件—验证—FPGA—特点与总结”。

## 2. 正式写作前统一口径

当前应以活跃 RTL、`data/soc/memory_map.json` 和 `data/soc/software_contract.json` 为主要依据。仓库中留有不同时期的 HXI、旧 superscalar core、RV32IMFD 等说明，正式文档不能混写。

# 正式技术文档目录

## 前置页

包括封面、摘要、关键词、快速预览、目录、图目录和表目录。

- 摘要用 500～800 字交代任务、CPU 架构、SoC、RT-Thread、传感器应用、验证方法和最终结果。
- 快速预览放系统总框图、板上照片、串口/OLED 运行图和一张关键指标表。
- 摘要中的频率、性能、资源和通过率必须来自最终基线，不能沿用历史数据。

## 第 1 章 项目概述

### 1.1 赛题背景、应用需求与设计目标

- 说明赛题要求，以及作品为何从 CPU 扩展到完整 SoC、RTOS 和传感器应用。
- 设计目标按 CPU、SoC、软件、外设、验证和 FPGA 六方面给出可验收指标。
- RISC-V 历史和 RTOS 常识只作必要铺垫，不展开成通用教材。

### 1.2 设计约束与开发平台

- 介绍 FPGA 型号、片上资源、时钟、ICCM/DCCM 容量和赛事交付方式。
- 说明无 Cache、无外部存储总线、I²C 开漏连接及板级电气条件带来的限制。
- 列出 RTL、仿真、软件和 FPGA 工具版本。

### 1.3 作品特点与完成情况

- 用表格列“目标—实现状态—验证证据—剩余工作”。
- 仿真通过、实现通过、bitstream 生成和实体板通过分开标记。
- 概括作品的主要特点，详细论证放到第 9 章。

本章建议材料：需求—实现对应表、项目完成状态表、开发平台表。

## 第 2 章 系统总体设计

### 2.1 软硬件总体架构

- 展示 `fpga_top → soc_top → CPU / 外设子系统` 的硬件层次。
- 同图标出启动代码、BSP、RT-Thread、驱动、MSH 命令和应用层。
- 说明 core 域、外设域、片上存储和板外器件之间的边界。

### 2.2 关键参数与接口关系

- 汇总 ISA/ABI、发射宽度、流水级数、存储容量、时钟、UART、I²C、RTOS 和 FPGA 器件。
- 说明 CPU 取指、DCCM 访问、本地 MMIO、中断和 Test Status 的主要接口。
- 详细位域、寄存器和信号表放附录。

### 2.3 典型数据流与运行场景

至少说明三条链路：

1. CPU 从 ICCM 取指并访问 DCCM/MMIO；
2. 串口输入 `light_read`，经 MSH、驱动和 I²C 得到 lux；
3. `oled_start` 生成 framebuffer，并经共享 I²C 刷新 OLED。

### 2.4 总体设计取舍

- TCM-only 的确定性和容量代价；
- 双时钟域对 CPU 性能与低速外设稳定性的平衡；
- I²C 采用有界轮询的原因；
- 仿真与 FPGA 共用同一软件镜像合同的意义。

本章建议材料：系统总框图、软硬件分层图、端到端数据流图、关键参数表。

## 第 3 章 CPU 核设计

### 3.1 CPU 来源、指令集与设计边界

- 说明上游基础版本，以及保留、裁剪、修改和新增的内容。
- 介绍 RV32I、M、F、Zicsr、Machine Mode 与 `ilp32f`。
- 明确 C、A、非对齐访问、Cache、外部总线等未支持项。
- 用“上游能力—本项目改动—验证证据”表准确界定团队工作。

### 3.2 双发射 9 级流水总体结构

- 画出取指、对齐、译码、双槽发射、执行、完成和退休的流水关系。
- 说明 I0/I1 的能力、配对条件、单发射退化条件和长延迟指令影响。
- 结合一组双发射和一组受限发射示例说明数据通路。

### 3.3 前端取指与分支预测

- 合并介绍 ICCM 取指、指令缓冲、对齐、BTB、BHT 和全局历史。
- 用正确预测和误预测时序解释 PC 选择、flush 和预测状态更新。
- 表项规模和索引公式只写当前配置，其他候选参数不进入正文。

### 3.4 译码、发射与相关性控制

- 说明整数、访存、分支、CSR、M 扩展和 F 扩展的译码分类。
- 给出 I0/I1 配对限制、结构冲突和 RAW 相关处理。
- 将 scoreboard、旁路、stall、replay 和流水清空放在同一控制链中说明。

### 3.5 执行与访存系统

- 介绍 ALU、分支判定、乘除法、地址生成、字节选通和对齐检查。
- 说明 DCCM bank 组织、load/store 路径、MMIO 识别和阻塞行为。
- 乘除法延迟、DSP 映射、DCCM 访问等细节作为本节内的表格或小段，不再单独列目录。

### 3.6 浮点与机器状态

- 说明 FPnew 的接入、请求/响应、运算类别和 RV32F 数据格式。
- 介绍 FPR、FCSR、舍入模式、异常标志和 RT-Thread 浮点上下文。
- 不写未启用的 FP64 能力；具体指令覆盖和延迟可放表格。

### 3.7 异常、中断、退休与性能观测

- 串联 CSR、精确异常、异步中断、流水恢复和顺序退休。
- 说明 timer、软件调度请求和 UART 外部中断的映射。
- 介绍 commit trace、性能计数器以及它们在 DiffTest 和 CoreMark 中的用途。

本章建议材料：CPU 总框图、9 级流水图、双发射限制表、分支恢复时序、DCCM 组织图、FPU 数据流、Trap/退休流程。

## 第 4 章 SoC 硬件设计

### 4.1 SoC 顶层与片上存储

- 说明 `soc_top`、CPU wrapper、ICCM/DCCM 和外设子系统的连接关系。
- 介绍 4 个 ICCM lane、8 个 DCCM bank 以及 FPGA BRAM 初始化。
- 将 ELF 到片上镜像的硬件视角放在本节，软件构建细节留到第 6 章。

### 4.2 MMIO 通路与地址空间

- 说明 LSU 本地 MMIO、地址译码、反压、单笔阻塞和错误响应。
- 给出 CODE、DATA、TIMER、UART、GPIO、SYSCTRL、I²C 的地址图。
- 完整寄存器位域移到附录 A。

### 4.3 时钟、复位与跨时钟处理

- 介绍差分时钟、MMCM、core 时钟和固定 50 MHz 外设时钟。
- 说明复位释放、MMIO toggle 握手、中断同步和状态信号同步。
- 用一张请求/响应时序图解释单 outstanding 和数据稳定条件。

### 4.4 中断、系统控制与测试状态

- 汇总 timer、软件调度请求和 UART 中断的 cause、触发方式和清除方式。
- 说明 SYSCTRL 中的身份、频率、复位原因、构建号和测试状态。
- 解释 PASS/FAIL magic、诊断码和 CoreMark 测量窗口如何贯通仿真与板上状态。

本章建议材料：SoC 框图、地址空间图、MMIO/CDC 时序、中断表、镜像映射图。

## 第 5 章 外设、传感器与显示系统

### 5.1 外设子系统设计

- 从系统角度介绍 Timer、UART、GPIO、SYSCTRL 和传感器接口的职责。
- Timer 的 64 位计数与 RT tick、UART 的 FIFO/波特率/中断、GPIO 的输入同步和输出控制都放在本节。
- 每个外设只保留关键工作原理和项目相关设计，不逐寄存器讲解。

### 5.2 传感器与显示硬件集成

- 以 BH1750 和 SSD1306 共用总线为主线，说明地址、供电、上拉、开漏和板卡引脚。
- I²C Master 的寄存器、状态机、ACK/NACK、超时、时钟拉伸和 bus recovery 作为本节内容，不再使用“I²C Master RTL”二级标题。
- 配一张硬件连接图和一张复合事务时序图即可覆盖模块细节。

### 5.3 设备驱动与共享总线管理

- 说明通用 I²C 层、BH1750 驱动、OLED 驱动和应用命令的分层。
- BH1750 的单次测量、180 ms 等待和定点 lux 换算在本节连续说明。
- OLED 的地址探测、初始化、framebuffer、分块刷新和启停语义放在同一链路。
- 交代 RT-Thread mutex、锁持有范围、NACK/超时传播和设备故障隔离。

### 5.4 用户命令与系统演示

- 以 `light_read`、`oled_start`、`oled_stop` 三条命令组织正常输出和错误输出。
- 演示顺序为：进入 MSH、读取光照、启动 OLED、停止 OLED、再次读取光照。
- 用串口截图和实物照片证明 OLED 停止后 BH1750 仍可使用，错误不会复位 SoC。

本章建议材料：外设框图、I²C 连接/时序、驱动调用图、共享总线时序、串口截图和实物照片。

## 4. 优先准备的图表

必备图：系统总框图、CPU 流水图、双发射限制图/表、分支恢复时序、SoC 地址图、CDC 时序、I²C 连接与事务时序、软件启动流程、DiffTest 流程、板级连接图。

必备表：关键参数、团队改动边界、ISA/CSR、Memory Map、外设/中断、软件来源分类、验证矩阵、回归结果、FPGA 签核、基线对比和已知限制。

## 5. 原始证据清单

- 最终 Memory Map、软件合同和编译 manifest；
- ISA summary、Spike DiffTest 日志和主动注错结果；
- I²C 单元测试日志与代表性波形；
- RT-Thread、MSH、CoreMark 和传感器 UART 原始日志；
- BH1750/OLED 接线与实物照片；
- Vivado utilization、timing、DRC、功耗（如有效）和 bitstream 信息；
- 固件、镜像、bitstream 的 SHA-256；
- 板上验收日期、环境、步骤和结果。

## 6. 正文写作规则

- 每节围绕“问题、设计、关键实现、取舍、验证”形成一条连续论述，不再按源码文件拆标题。
- 正文代码只放决定行为的短片段；完整寄存器、初始化数组和命令清单进附录。
- “仿真 PASS”“实现 PASS”“bitstream 生成”“板上 PASS”分开表述。
- CoreMark 同时给出编译参数、频率、迭代数、CRC、计时单位和测试平台。
- 资源、时序和功耗注明 FPGA 型号、工具版本、约束和活动率条件。
- VeeR EH1、FPnew、RT-Thread、CoreMark 标明来源，团队贡献集中写裁剪、适配、接口、外设、驱动、验证和 FPGA 集成。

## 7. 推荐写作顺序

1. 冻结 CPU、ISA、存储、时钟、中断和外设合同；
2. 完成第 2～5 章的架构图和硬件/外设说明；
3. 完成第 6 章的软件移植和构建链；
4. 跑最终回归并填写第 7 章；
5. 完成 FPGA 与实体板验收后填写第 8～9 章；
6. 最后写第 1 章、摘要、快速预览和总结；
7. 从代码、报告和 datasheet 反向检查每个数字与引用。
